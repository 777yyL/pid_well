# 标研 · 售前 Agent 工作台

面向部门内部的招标评估 Agent 应用。以项目组织多轮会话、招标原文、产品知识证据、结构化评估和人工复核，保留原 Pi 工作流的五项判断规则。

## 启动

需要 Node.js 22.19+ 和 pnpm 11，建议使用 Node.js 24。Node.js 24 为容器和本机验证版本。

开发与正式启动默认通过 `--use-system-ca` 信任操作系统证书，同时保留 HTTPS 证书校验。企业代理使用内部 CA 时，需将 CA 安装到系统信任库；容器也需要独立安装相应 CA。

```text
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://127.0.0.1:4317。首次使用创建管理员，进入「连接与运行设置」配置模型 Base URL、模型 ID、API Key 及 LLM Wiki API 地址。不预置账号、模型密钥或业务样例数据。

流程：新建项目并绑定明确的知识库项目 → 上传文件 → 告诉 Agent 评估目标 → 核对并确认抽取条款 → 让 Agent 继续匹配和复核 → 审阅证据或人工修正 → 导出报告。

## 运行结构

- React / Ant Design：项目、会话、计划、证据、复核与报告工作台。
- Fastify / TypeScript：鉴权、授权、项目与文件 API。
- `@earendil-works/pi-agent-core`：自主工具调用循环、多轮上下文及取消。
- Pi AI：OpenAI Chat Completions 兼容接口；模型须支持 SSE 与 tool calls。
- PostgreSQL：保存会话、执行事件、计划、结果、版本与审计。未设置 `DATABASE_URL` 时使用磁盘持久化 PGlite，方便单机运行和验证。
- LLM Wiki HTTP API：项目、读取、搜索与图谱。当前未实现 MCP 适配。

服务端不向 Agent 提供通用 shell 或任意文件访问工具。工具固定绑定当前项目；不允许写入产品知识库。

## 正式部署

公司内网试运行的服务器准备、HTTPS 接入、初始化、验收与备份恢复步骤见 [公司测试部署方案](deploy/COMPANY_TEST_DEPLOYMENT.md)。环境配置模板为 `deploy/company.env.example`。

```text
pnpm build
```

设置 `NODE_ENV=production` 后执行 `pnpm start`。配置项参考 `.env.example`。

部门部署推荐外部 PostgreSQL。当前调度为单实例，数据库 advisory lock 阻止多实例误抢任务；不要以多副本启动。设置并保持稳定的 `APP_ENCRYPTION_KEY`，其值为 32 字节的十六进制编码（64 字符）。密钥更换会使原配置密钥无法解密。

Docker Compose 需要在 `.env` 设置 `POSTGRES_PASSWORD` 和 `APP_ENCRYPTION_KEY`：

```text
docker compose up --build -d
```

Compose 默认仅在服务器 loopback 暴露 4317，由内网 HTTPS 反向代理提供访问。代理保留 Host / Origin；HTTPS 部署设置 `COOKIE_SECURE=true`。应用默认不信任转发 IP，避免任意请求伪造限流来源。根据部门代理拓扑再配置可信代理范围。

容器内的 `127.0.0.1` 指向容器自身。LLM Wiki 运行在宿主机时，工作台设置中使用 `http://host.docker.internal:19828`，并在 LLM Wiki 启用局域网监听与 token。已有知识库需保持服务在线；本项目不包含 LLM Wiki 服务端。

首次管理员初始化应在开放给部门前由负责人完成。新成员由管理员创建，项目负责人添加项目成员。

备份必须同时覆盖 PostgreSQL、`data/uploads`、`data/artifacts` 和加密密钥；仅备份数据库无法恢复原文件。PGlite 单机模式应停止服务后备份整个 `data`，不要复制正在写入的数据库目录。

## 数据与执行约束

- DOCX、XLSX、文本 PDF、UTF-8 Markdown / TXT；25 MB 上传上限。扫描 PDF 不自动 OCR，空文本或损坏文件显式失败。XLSX 读取全部可见业务工作表。
- 每份原文及知识库快照有固定 ID、哈希和行号。保存条款与证据时服务端验证摘录原文。
- 未确认条款可由 Agent 修正，已确认条款不可静默覆盖。人工修正的匹配结论不会被 Agent 覆盖。
- 所有条款确认、匹配、复核且交付依赖齐全后，才能生成正式报告。Excel、CSV、HTML 使用同一份结果；历史报告保存生成版本与证据索引。
- Agent 可用 `get_assessments` 按条款编号查询当前版本，或仅查询未复核条目；保存结果直接返回版本号，版本冲突会指出具体条款和最新版本。禁止通过重复保存或穷举版本来继续复核。
- 同项目仅一个活动任务，重复请求按幂等键去重。默认每 40 轮自动建立检查点、压缩上下文并继续执行（`MAX_AGENT_TURNS`）；任务总预算 400 轮（`MAX_TOTAL_AGENT_TURNS`），连续 12 轮没有新进展时暂停（`MAX_NO_PROGRESS_TURNS`），15 分钟超时，服务级并发为 2。上下文窗口和执行预算相互独立，1M 模型也受循环和时间保护。
- 断开浏览器不会取消执行。刷新页面按事件游标接续；服务重启将运行任务标记为中断，用户选择恢复后读取已有事实继续。中断的工具调用会补齐恢复记录，不盲目自动重放写入。
- 达到上下文安全预算或执行检查点时，自动生成语义摘要，持久化用户目标、计划、已读取原文区间与压缩次数，并保留最近的完整工具调用配对。摘要失败时使用数据库事实与阅读区间接续；取消仍能中止摘要和执行。摘要不替代原文、知识库证据和人工确认。压缩日志、可见会话和工具事件保留在数据库，不保留无限增长的模型推理上下文。未实现跨项目记忆。
- UI 当前使用带游标的增量轮询展示流式文本，模型侧使用 SSE；未实现 WebSocket 推送。

### 提供给销售的清单

「导出报告」菜单包含「销售项清单 · SPS 模板 XLSX」。独立文件首张表按 `sps销售项清单模板.xlsx` 的 10 列输出：序号、名称、产品类别、型号、技术规格、单位、数量、单价、合价、备注；第二张表记录来源和版本。完整 XLSX 和 HTML 报告也包含销售项汇总，CSV 为功能匹配明细。

清单从复核结果实际引用的实体快照生成，按产品、版本和模块 ID 去重，记录关联条款；识别 YAML、Markdown 表格、产品链接、列表字段、加粗章节标题和完整技术规格。数量优先使用实体明确提供的数量，否则留空供销售核定；有数量与单价时计算合价，不按匹配功能条数估算授权数量。备注包含报价说明、描述、必选、依赖、版本和缺失字段。引用版本冲突、交付依赖缺项时阻止正式导出。

## 验证与上线边界

```text
pnpm check
pnpm test
pnpm build
```

自动化测试使用隔离临时数据库和本地兼容模型协议服务器，验证真实 Pi 循环、工具执行、多轮上下文、幂等、取消、授权、证据、人工复核、报告及持久化，不代替真实模型质量验证。

真实 LLM Wiki 已验证项目列表、页面读取和搜索。真实模型需配置后用脱敏招标文件做验收，重点核对条款完整性、规格判断、版本与依赖覆盖。服务端校验可验证引用和流程完整性，不能证明 AI 的语义判断正确。

当前交付为可运行的首版产品代码；部门正式上线前仍需完成真实模型评估验收、外部 PostgreSQL 与容器部署验证、备份恢复演练、并发和大文件压力测试。SSO、MCP、OCR、分布式 Worker 尚未实现。
